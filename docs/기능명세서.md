## 1. 문서 안내

### 1.1 범위

이번 개발 범위(요구사항 정의서 v2의 구현·간이구현 22건)에 해당하는 화면 15개와 백엔드 기능 22개를 다룹니다. 이번 범위 밖 기능은 11.3에 따로 적었습니다.

### 1.2 이 문서를 읽는 법

| 표기 | 뜻 |
|---|---|
| S-01~S-07 | 신청자 화면 |
| A-01~A-08 | 관리자 화면 |
| BE-01~BE-22 | 백엔드 기능(기획서 9장) |
| R-01~R-16 | 규칙(기획서 8장) |
| MSG-01~ | 오류·안내 메시지(이 문서 10장) |
| 필수 | 비워 두면 다음 단계로 갈 수 없는 칸 |
| (제안) | 고객이 정하지 않아 우리가 임시로 정한 값 |

### 1.3 용어

| 용어 | 뜻 |
|---|---|
| 슬롯 | 시설·날짜·1시간 단위의 대관 칸. 예: 풋살장 2027-01-23 09:00~10:00 |
| 구민 단체 | 회원의 절반 이상(50% 이상)이 푸른구민인 단체 |
| 접수 기간 | 매월 1일 09:00부터 5일 18:00까지(5일이 휴일이면 다음 영업일 18:00). 다음 달 이용분을 받는다 |
| 추첨 | 접수 마감 뒤 슬롯별로 무작위로 1개 단체를 정하는 일 |
| 당첨·탈락·대기 | 슬롯별 결과. 추첨 전에는 대기 |

### 1.4 근거 문서의 우선순위

조례가 위이고 운영 규정이 세부입니다. 두 문서가 다르면 조례를 따릅니다. 이 문서의 숫자는 가상 조례·규정·대관료 표와 같습니다.

## 3. 공통 기능

### 3.1 로그인과 권한

| 항목 | 내용 |
|---|---|
| 역할 | 신청자(applicant), 관리자(admin). 시설 직원·팀장 분리는 추후 |
| 신청자 | 본인의 신청·결과·증빙만 볼 수 있다. 다른 단체 정보는 보이지 않는다 |
| 관리자 | 모든 관리 화면을 쓸 수 있다. 신청자 화면의 신청 기능은 쓰지 않는다 |
| 로그인 | 휴대전화 번호와 비밀번호. 연속 5회 실패하면 10분간 잠금(제안) |
| 세션 | 30분 동안 활동이 없으면 로그아웃(제안). 로그아웃 전에 입력 중이던 신청서는 복구하지 않는다 |
| 권한 없는 접근 | 관리자 화면에 신청자가 들어가면 MSG-20을 보여주고 S-01로 보낸다 |

### 3.2 반응형(신청자 화면)

| 구분 | 화면 너비 | 배치 |
|---|---|---|
| 모바일 | 767px 이하 | 1열. 표는 카드로 바꿔 보여준다. 달력은 시설 탭 + 날짜 목록 |
| 태블릿 | 768~1023px | 1열 또는 2열 |
| PC | 1024px 이상 | 2열 이상. 표와 월 달력을 그대로 보여준다 |

- 신청자 화면 S-01~S-07은 모바일(약 360px)과 PC(1280px) 모두에서 신청부터 결과 확인까지 끝낼 수 있어야 한다.
- 누르는 칸(버튼, 슬롯, 탭)은 높이 44px 이상으로 한다.
- 입력 칸의 글자는 16px 이상으로 해서 모바일에서 확대되지 않게 한다.
- 관리자 화면은 PC(1024px 이상) 기준이며, 작은 화면에서는 표를 가로로 밀어 볼 수 있게 한다(가정).

### 3.3 개인정보 표시

| 정보 | 가림 규칙 | 예 |
|---|---|---|
| 성명 | 가운데 글자를 `*`로 | 김*수, 두 글자는 김* |
| 휴대전화 | 가운데 네 자리를 `*`로 | 010-****-1234 |
| 주소 | 구 단위까지만 | 푸른구 ○○동 → 푸른구 |
| 본인 화면 | 본인 정보는 가리지 않는다 | |
| 관리자 목록 | 기본은 가린다. 상세 화면을 열 때만 원문을 보여주고 열람 계정·일시를 기록한다(BE-22) | |
| 추첨 기록 화면 | 단체명·대표자를 가린다. 당첨 신청은 접수번호로만 표시 | |

### 3.4 표기 규칙

| 항목 | 규칙 | 예 |
|---|---|---|
| 날짜·시간 | 한국 시간. 요일 포함 | 2027-01-23(토) 09:00~11:00 |
| 금액 | 원 단위, 천 단위 쉼표 | 84,000원 |
| 접수번호 | 신청 접수 시 부여 | A-2026-000123 형식 |
| 주말·공휴일 | 달력에서 색으로 구분하고 주말 요금 적용을 표시 | |

### 3.5 입력 검증과 오류

- 입력 오류는 해당 칸 바로 아래에 붉은 글씨로 보여주고, 저장하지 않는다.
- 같은 버튼을 연속으로 누르면 한 번만 처리한다(중복 제출 방지).
- 요금·겹침·이용 불가일·접수 기간은 서버에서 다시 검증한다. 화면에서 보낸 값을 그대로 믿지 않는다.
- 서버 오류는 MSG-21로 안내하고 입력한 내용은 유지한다.

### 3.6 비밀번호 규칙

8자 이상이며 영문·숫자·특수문자를 모두 포함한다(제안). 입력 칸의 글자는 가려서 보여주고, 가입 시 확인 입력을 한 번 더 받는다.

## 4. 신청자 화면 기능

### 4.1 S-01 메인

| 항목 | 내용 |
|---|---|
| 목적 | 이번 달 접수 일정과 바로가기를 한눈에 보여준다 |
| 권한 | 모두(비로그인 포함) |
| 관련 | R-01, BE-03, REQ-A01·A28 |

**표시 항목**

| 항목 | 내용 |
|---|---|
| 접수 상태 배지 | 접수 전 / 접수 중 / 마감 / 추첨 완료 |
| 접수 기간 | 시작·마감 일시, 남은 시간(접수 중일 때) |
| 추첨·발표 일정 | 추첨일, 발표일 |
| 바로가기 | 신청하기(S-04), 내 신청·결과(S-06), 규정 질문(S-07) |

**동작**

| 번호 | 사용자 동작 | 시스템 처리 | 결과 |
|---|---|---|---|
| 1 | 화면 열기 | 현재 접수 기간(BE-03) 조회 | 상태 배지와 일정 표시 |
| 2 | 신청하기 누르기 | 접수 중이면 S-04로 이동 | 접수 전·마감이면 버튼이 꺼져 있고 이유를 문구로 알림(접수 전: "○월 ○일 09:00에 열립니다", 마감: "접수가 마감되었습니다. 결과는 발표일에 확인하세요") |
| 3 | 내 신청·결과 누르기 | 비로그인이면 S-03으로 이동 | 로그인 후 S-06 |

**모바일/PC**: 모바일은 카드가 위에서 아래로, PC는 왼쪽에 일정, 오른쪽에 바로가기를 둔다.

### 4.2 S-02 회원가입

| 항목 | 내용 |

| 목적 | 단체 대표자 계정을 만든다. 개인정보 처리 동의 후에만 가입할 수 있다 |

| 관련 | R-02, R-09, R-13, BE-01, REQ-B07·A26 |

**단계와 입력 항목**

| 단계 | 항목 | 형식 | 필수 | 검증 |

| 2 대표자 | 성명 | 문자 | 필수 | 2자 이상 |
| 2 대표자 | 휴대전화 | 숫자 | 필수 | 010으로 시작하는 11자리, 이미 가입된 번호는 불가(MSG-02) |
| 2 대표자 | 비밀번호, 확인 | 문자 | 필수 | 3.6 규칙, 두 칸이 같아야 한다(MSG-05) |
| 3 단체 | 단체명 | 문자 | 필수 | |
| 3 단체 | 단체 유형 | 선택 | 필수 | 일반 동호회 / 장애인 단체 / 국가유공자 단체 / 구 소재 학교 / 노인 단체 |
| 3 단체 | 단체 주소 | 문자 | 필수 | 구 단위까지 |
| 3 단체 | 회원 수 | 숫자 | 필수 | 5명 이상(MSG-03) |
| 3 단체 | 푸른구민 회원 수 | 숫자 | 필수 | 회원 수 이하(MSG-04). 입력하면 "구민 단체 / 비구민 단체"를 바로 보여준다 |
| 4 인증 | 휴대전화 인증번호 | 숫자 6자리 | 필수 | 이번 범위에서는 인증번호 입력 화면까지만 만들고 개발용 고정 번호를 쓴다. 실제 문자 발송은 추후 |

**동작**

| 번호 | 사용자 동작 | 시스템 처리 | 결과 |
|---|---|---|---|

| 2 | 가입 완료 누르기 | member, org 저장. 동의 시각 저장. 비밀번호는 암호화한 값만 저장 | 가입 완료 화면 → 로그인(S-03) |

**모바일/PC**: 모바일은 단계마다 한 화면, PC는 한 화면에 단계를 모아 보여준다. 입력 도움말은 칸 아래에 둔다.

| 번호 | 관리자 동작 | 시스템 처리 | 결과 |

| 2 | 추첨 실행 누르기 | 마감 뒤인지, 이미 실행되지 않았는지 확인(7장) | 마감 전이면 MSG-14, 이미 실행했으면 MSG-15 |
| 3 | 확인 대화상자 | "마감 후 한 번만 실행할 수 있습니다. 실행할까요?" | 확인하면 실행 |

## 6. 규정 질의응답(AI) 상세

### 6.1 처리 흐름

| 단계 | 처리 | 담당 |
|---|---|---|
| 1 | 질문 입력 | 사용자 |
| 2 | 개인정보 형태(휴대전화·주민등록번호 등) 검사. 있으면 전송하지 않고 MSG-18 | 시스템 |
| 3 | 규정 조항 검색: 질문의 핵심 단어와 유의어로 조항을 찾아 관련도 순으로 상위 5~8개 선택 | 시스템 |
| 4 | 근거 충분성 판단: 관련도가 기준에 못 미치면 AI를 호출하지 않고 MSG-17 | 시스템 |
| 5 | AI 호출: 찾은 조항만 근거로 주고 아래 원칙으로 답하게 한다 | AI |
| 6 | 인용 검증: AI가 인용한 조항 번호가 검색 결과에 없으면 제거 | 시스템 |
| 7 | 금액 질문이면 계산 로직 결과를 답변에 붙인다 | 시스템 |
| 8 | 답변·근거 표시, 질의응답 기록 저장(개인정보 제외) | 시스템 |

### 6.2 AI에게 주는 원칙

1. 제공된 조항 안의 내용만 근거로 답한다.
2. 조례와 규정이 다르면 조례를 따른다고 밝힌다.
3. 답변에 조항 번호(문서·조·항)를 반드시 쓴다.
4. 금액을 직접 계산하지 않는다. 계산표가 제공되면 그대로 쓴다.
5. 추측하지 않는다. 근거가 없으면 "확인할 수 없습니다. 센터 담당자에게 문의하세요"라고 답한다.
6. 3~5문장의 쉬운 말로 답한다.

### 6.3 설정

| 항목 | 값 |
|---|---|
| 모델 | 경량 모델(Haiku 5.5)로 시작. 설정으로 변경 가능 |
| 답변 길이 | 최대 약 500 토큰 |
| 응답 제한 시간 | 10초(제안). 넘으면 검색된 조항 원문만 보여준다(MSG-19) |
| 키 관리 | 서버에서만 사용하고 화면 코드에 넣지 않는다 |
| 기록 | 질문(개인정보 제외), 인용한 조항 번호, 답변 방식(AI / 검색만 / 근거 없음) |

### 6.4 시험 질문과 기대 결과

조문 번호는 가상 조례·운영 규정 기준입니다.

## 7. 추첨 상세

### 7.1 실행 조건

- 관리자만 실행할 수 있다.
- 해당 접수 기간의 마감 시각이 지난 뒤에만 실행할 수 있다(MSG-14).
- 같은 접수 기간에 이미 추첨 기록이 있으면 실행할 수 없다(MSG-15). 재실행은 막는다.

### 7.2 처리 순서

| 단계 | 처리 |
|---|---|
| 1 | 해당 접수 기간의 모든 슬롯 신청(대기)을 (시설, 날짜, 시작 시각)별로 묶는다 |
| 2 | 묶음의 순서를 무작위로 섞는다 |
| 3 | 묶음을 차례로 처리한다. 신청이 1건이면 단독 선정한다 |
| 4 | 신청이 2건 이상이면 후보에서 "같은 시설·같은 주에 이미 2개를 당첨된 단체의 정기 대관 신청"을 뺀다. 남은 후보 중 균등한 확률로 1건을 뽑는다. 구민·감면 여부로 가중하지 않는다 |
| 5 | 후보가 없으면 해당 슬롯은 비워 두고 신청들은 탈락 처리한다 |
| 6 | 뽑힌 신청은 당첨, 나머지는 탈락으로 바꾸고 선정 사유 문구를 저장한다 |
| 7 | 슬롯별 기록(신청 건수, 방식, 당첨 신청)과 실행 기록(시각, 실행자, 규칙 버전, 난수 기록, 대상 수)을 저장한다 |
| 8 | 위 전체를 하나의 처리(트랜잭션)로 묶는다. 중간에 실패하면 모두 되돌린다 |

### 7.3 설계 원칙

- 같은 시설·시간에 당첨이 둘이 될 수 없다(데이터베이스의 유일 조건으로도 막는다).
- 난수 기록을 남기므로, 같은 입력으로 같은 결과를 다시 만들어 감사 때 확인할 수 있다.
- 접수 마감 뒤에는 새 신청을 받지 않으므로 추첨 중에 신청이 바뀌지 않는다.
- 실행 결과는 "결과 발표" 전까지 신청자에게 공개하지 않는다.

### 7.4 예

풋살장 2027-01-23(토) 09:00 슬롯에 5개 단체가 신청한 경우: 이 슬롯의 신청 건수는 5이고, 균등한 확률로 1개 단체가 당첨됩니다. 당첨 단체에는 "이 시간대에는 5건이 신청되어 무작위 추첨으로 선정되었습니다."를, 나머지 4개 단체에는 탈락 안내를 보여줍니다. 추첨 기록에는 신청 건수 5, 방식 "무작위추첨", 당첨 접수번호가 남습니다.

## 8. 요금·환불 계산 상세

### 8.1 계산식

| 항목 | 식 |
|---|---|
| 대관료 | 시간당 요금 × 이용 시간 (요금은 시설·구민 여부·평일/주말 기준 가상 조례 별표 1) |
| 감면액 | 대관료 × 감면율, 원 단위 반올림. 증빙 승인 후에만 적용 |
| 청구액 | 대관료 − 감면액 |
| 구민 단체 판정 | 구민 회원 수 ÷ 회원 수 ≥ 0.5이면 구민 요금 |
| 감면 중복 | 해당하는 감면율 중 가장 높은 하나만 적용 |

### 8.2 계산 예

| 번호 | 조건 | 계산 | 청구액 |
|---|---|---|---|
| 1 | 풋살장, 구민, 토요일, 2시간, 감면 없음 | 60,000 × 2 = 120,000 | 120,000원 |
| 2 | 풋살장, 구민, 토요일, 2시간, 노인 단체(30%) | 120,000 − 36,000 | 84,000원 |
| 3 | 실내체육관, 비구민, 평일, 3시간 | 45,000 × 3 = 135,000 | 135,000원 |
| 4 | 다목적실A, 구민, 평일, 2시간, 장애인 단체(50%) | 20,000 − 10,000 | 10,000원 |
| 5 | 장애인 단체(50%)이면서 노인 단체(30%) | 높은 하나만 적용 → 50% | |
| 6 | 회원 10명 중 구민 5명 | 50% → 구민 요금 | |
| 7 | 회원 11명 중 구민 5명 | 약 45.5% → 비구민 요금 | |

### 8.3 환불 계산

기준은 이용일의 N일 전 날짜의 24:00까지 접수된 취소입니다.

| 취소 시점 | 환불율 | 예: 청구액 84,000원 |
|---|---|---|
| 이용일 7일 전까지 | 100% | 84,000원 |
| 이용일 3일 전까지(7일 전 초과) | 50% | 42,000원 |
| 그 이후(2일 전~당일), 노쇼 | 0% | 0원 |
| 센터 사정(공사·행사·점검·우천 등) | 100% | 84,000원 |

이번 범위에서는 환불액을 계산해 안내하는 데까지만 합니다. 실제 결제 취소와 환불 처리는 추후입니다.
